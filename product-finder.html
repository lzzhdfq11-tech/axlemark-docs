Product finder

The Axlemark product finder is a built-in compatibility selector: shoppers pick what they own, such as a vehicle, a phone, a printer or a tire size, in up to three dropdowns and see only the products tagged to fit it. The choice is remembered, shown in the header and checked on every product page. This guide also covers the tag-based size finder and the shop-by-part vehicle diagram.

How it works

The finder is driven by product tags. Every entry in your finder list has a tag. A product fits an entry when the product carries that tag, or the tag of an entry above it.

  • Levels: one to three, for example Make → Model → Year, Brand → Device → Generation, Brand → Series → Printer model or Width → Profile → Rim.
  • Results: after choosing, shoppers land on the results collection filtered by the deepest selected tag.
  • Saved selection: stored on the shopper’s device and shown as “My vehicle: …” in the header, with Change and Clear.
  • Fit check: the Fitment check block on product pages compares the saved selection with the product’s tags.

Tag your products

Add tags in Products → (product) → Tags, with the bulk editor, or with a CSV import.

Product tagResult
model-a1Fits Model A1, all of its years.
make-aFits every model of Make A (a parent tag).
universal-fit (your universal tag)Shows Universal fit on the product page and is linked from every results page.
None of theseShows a neutral Check compatibility or Not confirmed for your …. The theme never says a product fits without a matching tag.
  • Use lowercase letters, numbers and hyphens: model-a1, brand-a, size-205-55-r16.
  • Tags are compared the way Shopify builds tag URLs, so Model A1 and model-a1 count as the same tag. Lowercase-hyphen tags are still recommended.
  • A product that fits several vehicles or devices simply gets several tags.
  • Tags are visible in your admin only; shoppers see the entry labels.

Which one is used where?

If the Product finder section has entries, that section uses them. Everywhere else (header, product pages, results page) the data file is used. Without a data file, the header and product pages reuse the entries the shopper last saw in the Product finder section, so for small lists with no file, place that section on the home page.

Option A: section blocks

  1. In the theme editor, add the Product finder section to your home page (the presets include it).
  2. Add one Finder entry block per first-level item, for example Make A.
  3. Fill in Label, Product tag (blank means a tag is made from the label, so Make A becomes make-a) and Second level.

Second level takes one line per item, Label | tag | years. Years are optional:

Model A1 | model-a1 | 2010-2018
Model A2 | model-a2 | 2016-
Model A3 | model-a3

2016- means “2016 to the current year”. When an item has years and a third level label is set, the third dropdown lists those years. A blank tag is made from the label.

Option B: JSON data file

  1. Create a .json file in the format below (or convert a spreadsheet, see Converting a spreadsheet).
  2. Upload it in Content → Files and copy the file’s URL.
  3. Paste it into Theme settings → Product finder → Finder data file URL and save.
Use a Shopify Files URL

The URL must be the address Shopify gives the file in Content → Files, or a file served from your own store domain. Addresses on other websites are ignored for security, and the finder then shows “The list could not be loaded”.

Shoppers’ browsers keep the file for the current visit. When you change it, upload it again under a new name and update the URL.

JSON format

The file is a list of first-level entries. Each entry can have children (the next level) and/or years.

FieldRequiredMeaning
labelYesText shown in the dropdown.
tagYes*Product tag for this entry (lowercase letters, numbers and hyphens). *An entry without a tag can still be chosen, but shoppers are sent to the tag of the entry above it.
childrenNoEntries for the next level. Up to three levels in total; deeper levels are ignored.
yearsNo[from, to]. null as to means “until now”. Used for the next level when there are no children. Years are for display and the saved label; matching uses tags.
urlNoSend shoppers to this page instead of the tag results, for example a dedicated collection.
popularNoFirst level only: also listed in a “Popular” group at the top of the dropdown.

Example: vehicles (Make / Model / Year)

[
  {
    "label": "Make A",
    "tag": "make-a",
    "popular": true,
    "children": [
      { "label": "Model A1", "tag": "model-a1", "years": [2010, 2018] },
      { "label": "Model A2", "tag": "model-a2", "years": [2016, null] }
    ]
  },
  {
    "label": "Make B",
    "tag": "make-b",
    "children": [
      { "label": "Model B1", "tag": "model-b1", "years": [2012, 2020] },
      { "label": "Model B2", "tag": "model-b2", "url": "/collections/model-b2-parts" }
    ]
  }
]

Model B2 sends shoppers to its own collection through url.

Example: printers and IT devices (Brand / Series / Model)

The same format works for ink, toner, drums, batteries, memory and other parts that fit specific devices. Set the level labels to Brand, Series and Model, and What shoppers select to printer, so messages read “My printer” and “Fits your printer”. Tag each cartridge with every model it fits, for example printer-p100 and printer-p200, or with a series tag such as series-p when it fits the whole series.

Results page: the finder template

Shoppers are sent to <results collection>/<tag>?view=finder, for example /collections/all/model-a1?view=finder. The view=finder part loads the finder collection template, which Axlemark includes with two sections:

  1. Finder results intro: shows “Parts for Make A Model A1”, the number of matching products, a Change selection control, a link to universal-fit products and an honest message when nothing is listed yet.
  2. Collection products: the normal product grid with filters and sorting.

To edit it, open the template picker in the theme editor and choose Collections → finder. If the template is missing (for example after deleting it), create a collection template named finder and add the Finder results intro section above the product grid. If you choose a real collection as the results collection, you can also assign the finder template to it.

Size finder

The Size finder section is a separate, tag-driven finder for products sold by size, such as tires, wheels, filters or batteries. Instead of a data file, it reads the product tags of one collection and turns every tag that matches a tag pattern into a valid size. Shoppers pick each part of the size in turn, only combinations that exist are offered, and the button opens the collection filtered by that tag.

  1. Tag each product with its size in one fixed format, for example tyre-205-55-r16 for a 205/55R16 tire.
  2. Add the Size finder section, choose the collection that holds these products and enter the matching Tag pattern: tyre-{1}-{2}-r{3}. {1}, {2} and {3} are the size parts; the text between them must match your tags exactly.
  3. Set the labels for each part, for example Width, Profile and Rim. One to three parts are supported.
  4. Optionally add Popular size blocks (label and tag) for one-click chips, and a help link explaining where to find the size.
Tag patternMatching tagDropdowns
tyre-{1}-{2}-r{3}tyre-205-55-r16Width 205 → Profile 55 → Rim 16
wheel-{1}x{2}wheel-17x7Diameter 17 → Width 7
battery-group-{1}battery-group-48Group size 48

The popular size chips and the “All” link work without JavaScript. Use the Size finder for size-based products and the product finder for vehicles or devices; both can be on the same page.

Shop-by-part vehicle diagram

The vehicle diagram is an exploded view, like the figures in a workshop manual, that lets shoppers browse by where a part sits on the vehicle. They switch between hatchback, sedan, SUV and pickup, and between the exterior and interior views. Every hotspot is a numbered callout (01, 02 …), and a parts index repeats the same numbers and names. Selecting a callout opens a panel with the part name, a short text and links to shop; each index row links straight to the part’s collection (or its first link, or a search), and hovering a row highlights its callout. It uses original artwork with no vehicle brands, works with the keyboard and needs no images from you.

The drawing is set in a figure plate with a FIG label and the drafting grid, and is drawn in the Line art colour from Theme settings → Catalog style (blueprint blue in the Axlemark preset). In the Shop by part section the parts index sits beside the drawing; in the Split hero it is a ruled legend row under the drawing. The line drawing animates in once, and not at all for shoppers who prefer reduced motion.

It is available in two places:

  • The Shop by part section, on its own.
  • The Split hero section with Right column → Content set to Vehicle diagram (the Split hero with vehicle diagram preset), next to the finder card.
  1. Choose which body styles to show and which one appears first. Turn off the interior view if you do not need it.
  2. Add a Hotspot block for each part area (up to 12), choose Exterior or Interior, and drag the horizontal and vertical position sliders until the dot sits on the part.
  3. Enter the part name and choose a collection for the Shop button, or add up to three links (for example front and rear brake pads). With no collection and no links, the hotspot links to a search for its part name.

The compatibility (fitment) block

Add Fitment check to the Product information section (it is in the default product template, near the part number). It compares the shopper’s saved selection with the product’s tags and shows its verdict as a catalog stamp, a boxed uppercase label you can read across the room (FITS YOUR …, UNIVERSAL FIT, CHECK FIT or NOT CONFIRMED), with one of four messages:

MessageWhen
Fits your Make A Model A1The product carries the selected tag or one of its parent tags.
Universal fitThe product carries your universal fit tag. A note asks shoppers to check sizes and specifications.
Check compatibility — select your vehicleNothing is saved yet. With Show finder when nothing is selected on, a compact finder with a Check fit button appears right in the block.
Not confirmed for your …A selection is saved but the product has no matching tag. Shoppers are asked to check the details or contact you before ordering.

Fit in the cart and on product cards

  • Cart: every line in the cart drawer and on the cart page repeats the check for that product (“Fits your …”, “Universal fit” or “Not confirmed for your …”). With Add the shopper’s selection to the order on, the counter receipt under the lines shows the saved vehicle or device as a stamp.
  • Catalog plates and the parts table: the status dot shows your Status badges from tags rules or “Universal fit” for products with the universal tag, otherwise the stock state. Cards do not compare against the saved selection; use the finder results page for that.

Settings: Heading (default “Compatibility”) and Show finder when nothing is selected. Check fit saves the selection without leaving the product page. Pair the block with a specifications table or a collapsible tab listing compatible models, so shoppers can confirm the fit themselves.

What shoppers see

  1. On the home page or in the header, they choose Make A, then Model A1, then 2016, and select Find parts.
  2. They land on “Parts for Make A Model A1 2016” with the matching products, filters and a link to universal-fit products.
  3. The header now shows “My vehicle: Make A Model A1 2016” with Change and Clear.
  4. Every product page shows a stamp saying whether the product fits, is universal, or is not confirmed.
  5. In the cart, each line repeats the fit check, so a wrong part is easy to spot before checkout.
  6. The selection stays on their device for future visits until they change or clear it.

If no product carries the selected tag yet, the results page says “No products are listed for … yet” and suggests a broader selection, universal-fit products or contacting you.

Converting a spreadsheet to JSON

Keep a sheet with one row per lowest-level entry:

level1level1_taglevel2level2_tagfromto
Make Amake-aModel A1model-a120102018
Make Amake-aModel A2model-a22016

Export it as CSV, then group the rows by level1: each group becomes one entry, its rows become children, and from/to become years (an empty to becomes null). Any CSV-to-JSON converter or a short spreadsheet script can do this. Check the result with a JSON validator before uploading.

Finder FAQ

Does the finder use metafields or an app?

No. It works with product tags and data you add in the theme (section blocks or a JSON file). No app, external service or account is needed.

How large can my list be?

Section blocks suit lists of up to a few dozen first-level entries. For hundreds or thousands of entries, use a JSON data file. The file is downloaded once per browser session, so keep it lean: only label, tag and the optional fields you need.

Do years affect which products are shown?

No. Years are shown in the third dropdown and in the saved label, but matching uses tags. If parts differ by year range, make each range its own entry with its own tag (for example model-a1-2010-2014 and model-a1-2015-2018), using children instead of years.

Why does a product show “Not confirmed for your …”?

The product does not carry the selected entry’s tag, any parent tag or the universal tag. Add the right tag to the product, or add compatibility details in a collapsible tab or specifications table so shoppers can check.

I updated my JSON file but shoppers still see the old list.

Browsers keep the file for the current visit. Upload the new file under a new name and update Finder data file URL, so every new visit loads it right away.

The finder says “The list could not be loaded”.

The file is not valid JSON, or the URL is not a Shopify Files URL or a file on your own store domain (other addresses are ignored for security). Validate the file with any JSON validator, upload it in Content → Files and paste the URL Shopify shows. Shoppers can still use Browse all products in the meantime.

Does it work with collection filters?

Yes. The results page is a normal collection page, so filters, sorting and pagination from the Collection products section all work on top of the finder selection.

Is shopper data stored or sent anywhere?

The saved selection is stored only in the shopper’s own browser (local storage) so it can be shown in the header and checked on product pages. It is not sent to your store or to any third party, and shoppers can remove it with Clear.

How do I turn the finder off?

Uncheck Theme settings → Product finder → Enable product finder. This hides the finder sections, the header strip and the product page fit check. To hide only the header strip, uncheck Show saved selection in header.
